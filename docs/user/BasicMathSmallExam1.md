# BasicMathSmallExam1 サンプル

## 教材への取り込み

利用者の4ファイルを `data/assignments/BasicMathSmallExam1/` に複製し、5つの小問に整理しました。答案42は `s42`、答案43は `s43` です。原本は変更しません。

問題PDFと模範解答PDFは、本文を抽出したうえで描画画像を確認し、問題文・模範解答・機械処理用ルーブリックへ転記しました。各PDFのSHA-256をテンプレートに記録し、別のPDFへ置き換わった場合は準備コマンドが停止します。**任意のPDFから採点基準を自動確定する機能ではありません。**

修正版の模範解答ではグラフのx軸との交点が2つ合わせて5点で、試験全体100点です。

| 設問ID | 内容 | 配点 |
|---|---|---|
| q01_1 | 三次方程式の全解 | 途中式10 + 正答10 |
| q01_2 | 複素数を含む三次方程式の全解 | 途中式10 + 正答10 |
| q02_1 | 因数分解・平方完成 | 各10 |
| q02_2 | 放物線のグラフ | 向き・頂点・x軸交点2つ・y軸交点、各5 |
| q03 | -1を三重根とする三次方程式 | 正答20、考え方のみ正しい場合10 |

途中式の「5点ないし10点」等について、原文だけでは具体的な境界が確定しないため、ルーブリックに暫定の運用定義と教員確認事項を明記しています。既知の100点・75点に合うように基準を逆算してはいません。点差が出たら、まず小問別の認識結果と採点根拠を確認してください。

今回のグラフは問題文の関数で定義できるため、採点にはその関数と元答案画像を渡します。模範解答のグラフ画像自体は追加添付しません。答案のグラフはOCRだけで評価せず、Ornithに元画像を渡します。

## 再生成

既存の課題を上書きしないため、新しい出力先を指定します。

```bash
.venv/bin/python -m scoring prepare-sample \
  --source testData/BasicMathSmallExam1 \
  --output data/assignments/BasicMathSmallExam1-copy
```

PDFを差し替えた場合は `examples/basic-math-small-exam1/questions/` の問題・解答・基準を再確認して更新し、その確認後に `source-pdf-hashes.json` も更新してください。ハッシュだけを書き換えると、古い基準を新PDFへ適用してしまいます。

既知点は `data/evaluation/BasicMathSmallExam1-expected.json` に保存しています。再生成コマンドは既知点を生成も読み込みもしません。このファイルは課題ディレクトリ外に置き、runの入力やモデルへのリクエストに含めません。

## 実装範囲と制約

- llama.cppの `/v1/models` と `/props` でモデルID・量子化（設定時）・visionを確認します。互換API一般への対応ではありません。
- 推論は `/v1/chat/completions` にbase64のPNG/JPEGを添付します。各小問の照合・採点は別リクエストです。
- RicohとOrnithには元画像を送り、Uni-MuMERにはRicohの領域指定に従った切り出しを送ります。画像は縮小しません。複数ページも明示された順番で添付します。画像数・コンテキストの上限に達した場合はAPIエラーとして止まり、黙って入力を捨てません。
- Ricoh・Ornithには段階ごとにJSON Schemaを指定し、照合文は文字列、採点点数はルーブリックの許容値に制約します。それでも、構造違反・途中打ち切り・根拠の欠落があれば停止します。失敗記録と生レスポンスを残し、原因修正後に再開します。APIが黙って切り詰める独自設定の検出や、事前の厳密な画像トークン計算は未実装です。
- 観点のscore=nullは合計もnullにします。0点とは区別します。不確実箇所は人手確認へ引き継ぎます。
- 入力・設定・プロンプト・実装ファイルをrunのmanifestに記録します。再開時はハッシュを照合します。モデルGGUFの全ハッシュやホストのピークメモリは未取得です。
- 教員による確定点の入力UI・編集コマンドは未実装です。仮採点結果を直接上書きせず、別ファイルに教員の確認結果を保管してください。
- `max_retries` は現実装では0のみの運用です。自動再試行は行いません。通信失敗時は同じコマンドを再実行します。
- Ricohの全体OCRと画像照合で特定した数式領域をUni-MuMERへ逐次送信し、Ornithにはページごとの `ocr[page_id].ricoh` と `ocr[page_id].unimumer` を渡します。Uni-MuMERは自由形式の出力からLaTeXを抽出し、reasoningの説明文は渡しません。
- 3モデル常駐が不安定な場合は、`--stage ocr --ocr-engine ricoh`、`--stage ocr --ocr-engine unimumer`、`--stage grade` の順で、必要に応じて手動でモデルを切り替えます。
